## 2. สิ่งที่ทำเสร็จสมบูรณ์แล้วและทำงานอยู่ในแกนกลาง (Completed & Active Features)

### 2.1 ระบบตอบแชทอัตโนมัติ 24 ชม. (แม้ปิดคอมพิวเตอร์)
- **Cloud Keep-Alive (`followup.py`):** ยิง `/health` ทุก 60 วินาที ป้องกันเซิร์ฟเวอร์ Render หลับ
- **Active Facebook Graph API Auto-Responder (`followup.py`):** ดึงแชทล่าสุดจาก Facebook Page ข้าวบุกสุขใจทุก 60 วินาที หากพบข้อความลูกค้าที่ยังไม่ได้รับคำตอบเกิน 35 วินาที บอทจะประมวลผลและตอบกลับให้อัตโนมัติทันที (ป้องกันกรณี Meta Webhook ส่งไม่ถึง)
- **ป้องกัน `last_interaction_time` เพี้ยน (`database.py`):** ข้อความอัตโนมัติจากบอทเบื้องหลัง (`AI บริการหลังการขาย`, `AI บอทขุดแชท`, `AI แจ้งสถานะพัสดุ`, `AI ติดตาม`) จะไม่ไปอัปเดตเวลา `last_interaction_time` ของลูกค้า ทำให้แชทเก่าที่ปิดการขายไปแล้วไม่ถูกดึงกลับมาเป็นแชทใหม่

### 2.2 กฎเหล็กการปิดการขายและทวนออเดอร์ (อัปเดตตามคอมเมนต์คุณแอมมี่ & คุณนัด)
- **ห้ามให้ลูกค้าพิมพ์คำว่า `"ยืนยัน"` ซ้ำ (`prompt_engine.py`, `audit.py`):** เมื่อลูกค้าแจ้งขนาดสินค้า + ชื่อ-ที่อยู่-เบอร์โทร + เลือกวิธีชำระเงิน (เช่น เก็บปลายทาง) ครบถ้วนแล้ว บอทจะทวนรายการสั่งซื้อ แนบแฮชแท็ก `#BUY<ยอดเงิน>` แยกกล่องข้อความเดี่ยว และกล่าวขอบคุณแจ้งจัดส่งทันที (`state="completed"`, `image_key="none"`) โดยไม่ส่งรูปโปรโมชั่นซ้ำ และไม่บังคับให้ลูกค้าพิมพ์ `"ยืนยัน"` ซ้ำอีก
- **แยกกล่องข้อความ `#BUY<ยอดเงิน>` เดี่ยว 100% (`audit.py`):** แฮชแท็ก `#BUY459`, `#BUY499`, `#BUY899`, `#BUY939` ฯลฯ จะถูกแยกออกเป็น **1 บับเบิลเดี่ยวๆ (`#BUY...` ล้วนๆ)** ห้ามปนกับข้อความอื่น เพื่อให้ระบบ ROI Tracking ของคุณแอมมี่จับยอดได้ตรง 100%
- **ตัวกรองและซ่อมประโยคตอบรับคำขอบคุณ (`llm.py`, `audit.py`):** ดักจับประโยคที่ตกคำว่า `"ยิน"` (เช่น `"ดีมากๆค่ะขอบพระคุณมากๆนะคะ"` ในเคสคุณ `Gus Sasi`) และแปลงเป็นประโยคเต็มที่สุภาพและเว้นวรรคถูกต้องทันที: `"ด้วยความยินดีเลยค่ะ 😊 ขอบพระคุณที่ไว้วางใจให้ข้าวบุกสุขใจดูแลมื้ออร่อยนะคะ 💚🙏"`
- **อัปเดตคลังคำตอบ FAQ ล่าสุด (`config.json`, `line_group_config.json`):**
  - เรทราคาส่ง 100 ถุง: `60g = ถุงละ 25.- (2,500.-)`, `500g = ถุงละ 165.- (16,500.-)`, `1kg = ถุงละ 290.- (29,000.-)` (ยังไม่รวมค่าจัดส่งตามจริง)
  - อายุการเก็บรักษา: `"ข้าวบุกสุขใจสามารถเก็บได้นาน 1 ปีในอุณหภูมิห้องปกติ ไม่จำเป็นต้องแช่ตู้เย็นเลยค่ะ"`

### 2.3 ระบบบอทขุดแชทลูกค้าที่เงียบหายไป (3-Stage Ghost Re-engagement Bot — `followup.py`)
- **ตรวจจับ Stage จากข้อความจริง (`detect_reengage_stage_from_text`):** ป้องกันการส่งข้อความขุดซ้ำเมื่อเซิร์ฟเวอร์รีสตาร์ทหรือ Deploy ใหม่
- **บังคับระยะห่างขั้นต่ำระหว่าง Stage:**
  - `Stage 1`: ลูกค้าเงียบไปอย่างน้อย `>= 1.0 ชม.`
  - `Stage 2`: ต้องห่างจาก `Stage 1` อย่างน้อย `>= 5.0 ชม.` (รวม `>= 6.0 ชม.`)
  - `Stage 3`: ต้องห่างจาก `Stage 2` อย่างน้อย `>= 12.0 ชม.` (รวม `>= 20.0 ชม.`)
- **บล็อกลูกค้าที่แจ้งเบอร์โทร/ที่อยู่แล้ว:** หากในแชทมีเบอร์โทรศัพท์ 10 หลัก หรือที่อยู่จัดส่งแล้ว ระบบจะข้ามการขุดแชททันที (ป้องกันการทักซ้ำลูกค้าที่สั่งเก็บปลายทางแล้ว เช่น เคสคุณ `Sam Siri`)
- **คลังข้อความสุ่มหลายแพทเทิร์น (Randomized Multi-Pattern Pools):** สุ่มข้อความทั้งแบบสั้น 1 กล่อง, กลาง 1 กล่อง, และยาว 2 กล่อง ไม่ให้ข้อความเรียงเหมือนกันทุกแชท

### 2.4 ระบบแจ้งเตือนเลขพัสดุ 2 จังหวะ (2-Stage Parcel Tracking Notifier — `parcel_tracker.py`)
- **จังหวะที่ 1 (เมื่อขนส่งเข้ารับพัสดุแล้ว):** ส่ง **2 กล่องข้อความ** (กล่องแรกเป็นการ์ดแจ้งขนส่ง `J&T Express` + เลขพัสดุ / กล่องที่สองเป็นข้อความอุ่นใจว่าจะคอยติดตามพัสดุให้จนถึงมือ)
- **จังหวะที่ 2 (เมื่อพัสดุจัดส่งถึงมือลูกค้าแล้ว):** ส่ง **1 กล่องข้อความสั้นกระชับ** (ขึ้นต้นด้วย `✅` หรือ `🎉` แจ้งเวลาที่จัดส่งสำเร็จโดยไม่ส่งบล็อกเลขพัสดุซ้ำ) เพื่อให้เห็นความแตกต่างจากจังหวะที่ 1 อย่างชัดเจน

### 2.5 ระบบเชื่อมต่อ JST ERP และรายงานสรุปยอดขาย + สต็อกคงเหลืออัตโนมัติ (`jst_erp.py`, `daily_sheet_report.py`)
- **ตั้งค่าขนส่งและอนุมัติออเดอร์อัตโนมัติ (`auto_fix_missing_express_orders`):** ตรวจจับออเดอร์ที่ขึ้นสถานะ `ผิดปกติ (ยังไม่ตั้งค่าการขนส่ง)` ใน JST ERP แล้วผูกขนส่ง **J&T Express (`ExpressId: 219956`)** พร้อมกดอนุมัติ (`Audit`) ส่งเข้าคลังให้อัตโนมัติทุก 10 นาที
- **ตรวจสลิปโอนเงินอัตโนมัติ (`verify_and_auto_confirm_jst_slips`):** ตรวจสลิปที่ติด `Fail (เวลาชำระเงินไม่ตรงกัน)` ใน JST ERP แล้วกดยืนยันให้อัตโนมัติเมื่อยอดเงินและรหัสอ้างอิงสลิปถูกต้องและไม่ซ้ำ
- **กรองออเดอร์ซ้ำในรายงานสรุปยอด (`build_daily_sales_sheet_rows`):** หากในวันเดียวกันหรือข้ามวันมีออเดอร์ `ManualOrder` เบอร์โทรซ้ำกันระหว่างแอดมินคีย์มือกับบอท (`FB: ...`) ระบบจะนับเฉพาะใบหลักของแอดมินเพียงใบเดียว ไม่นับยอดซ้ำ
- **สรุปยอดลง Google Sheets เวลา 01:00 น. & แจ้งเข้ากลุ่มไลน์เวลา 07:00 น.:** รายงานยอดขายแยกช่องทาง (`Facebook`, `TikTok`, `Shopee`), ยอดโอน / COD, จำนวนสินค้าที่ตัดสต็อก (`60g`, `500g`, `1kg`), ยอดเทียบ `#BUY` ROI Tracking และ **ยอดสต็อกคงเหลือในคลังล่าสุด**

## 3. สิ่งที่ยังติด ยังค้างคา หรือยังทำไม่สำเร็จ (Pending / Incomplete / Known Bottlenecks)

### ⚠️ 3.1 การคีย์ออเดอร์จาก Facebook เข้า JST ERP อัตโนมัติ (`AUTO_SYNC_ENABLED` ปัจจุบันปิดไว้เป็น `False`)
- **สาเหตุที่ยังปิดไว้:** เนื่องจากช่วงที่ผ่านมามีแอดมินคนคีย์ออเดอร์เข้า JST ERP ตอนกลางคืนด้วยตัวเอง เมื่อบอทคีย์ออเดอร์ (`FB: ...`) เข้าไปด้วยจึงเกิดออเดอร์ซ้ำ 2 ใบในชื่อลูกค้าคนเดียวกัน (เช่น เคสวันที่ 31 ต.ค. ที่ทั้งใบที่บอทคีย์ตอน 13:30 น. และใบที่แอดมินคีย์ซ้ำตอน 20:46–20:50 น. ของ `ครูเล็ก`, `โยษิตา`, `สุกัญญา` ถูกส่งเข้าคลังทั้งคู่)
- **สถานะปัจจุบัน:** ตั้งค่า `AUTO_SYNC_ENABLED = False` ใน `messenger-engine/app/jst_erp.py` เพื่อป้องกันไม่ให้บอทสร้างออเดอร์ชนกับแอดมินคน และป้องกันไม่ให้รายการเคลม (`⭕เคลม⭕`) ถูกดึงมาสร้างเป็นออเดอร์ขาย
- **สิ่งที่ต้องทำต่อ:**
  1. ตรวจสอบพัสดุซ้ำ 3 รายการของวันที่ 31 ต.ค. (`ครูเล็ก #233258/#232992`, `โยษิตา #233253/#232993`, `สุกัญญา #233251/#232994`) กับทางขนส่ง/คลังสินค้า
  2. เมื่อต้องการให้บอทคีย์ออเดอร์แทนแอดมิน 100% (โดยให้แอดมินหยุดคีย์มือ) สามารถเปิด `AUTO_SYNC_ENABLED = True` ได้ทันที (ระบบล็อกเวลาคีย์ไว้เฉพาะช่วง 06:00–06:59 น. และขยายการเช็กเบอร์ซ้ำย้อนหลังเป็น 30 วันเรียบร้อยแล้ว)

### ⚠️ 3.2 อายุของ Session Cookie ในระบบ JST ERP (`DEFAULT_JST_COOKIE`)
- **สิ่งที่ยังติด:** ระบบเชื่อมต่อ JST ERP (`asia-web.jsterp.com`) ทำงานผ่าน Browser Session Cookie เนื่องจากยังไม่มี Official OpenAPI Token แบบถาวรจาก Jushuitan
- **ผลกระทบเมื่อ Cookie หมดอายุ:** หาก Cookie หมดอายุ (ทุกๆ ประมาณ 7–14 วัน หรือเมื่อกด Logout ในเว็บ JST) บอทจะดึงยอดขายและสต็อกสดจาก JST ERP ไม่ได้ชั่วคราว (จะใช้ค่าสำรองจาก `line_group_config.json` และ Facebook `#BUY` แทน)
- **วิธีแก้ไขเมื่อหมดอายุ:** คัดลอก Cookie ใหม่จากหน้าเว็บ JST ERP มาอัปเดตผ่าน `POST /api/jst/config` หรือในไฟล์ `messenger-engine/app/jst_erp.py`

### ⚠️ 3.3 ฐานข้อมูล SQLite บน Render (`Ephemeral Disk` เมื่อมีการ Deploy ใหม่)
- **สิ่งที่ยังติด:** เซิร์ฟเวอร์ Render ใช้ดิสก์ชั่วคราวสำหรับไฟล์ SQLite (`buksukjai_chat.db`) ทุกครั้งที่ Push โค้ดใหม่ขึ้น GitHub เพื่อ Deploy ข้อมูลใน SQLite จะถูกรีเซ็ต
- **การป้องกันที่ทำไว้แล้ว:** ระบบดึงประวัติแชท Facebook ย้อนหลังผ่าน Graph API อัตโนมัติทุกครั้งที่เริ่มทำงาน และเก็บข้อมูลสำคัญ (`line_group_config.json`, `audit_lessons_learned.json`, Google Sheets) ลงใน Git และ Cloud
- **สิ่งที่ยังทำไม่สำเร็จ 100%:** ประวัติแชทฝั่ง **LINE OA ของลูกค้า** ไม่สามารถดึงย้อนหลังผ่าน LINE API ได้เมื่อ SQLite รีเซ็ต หากต้องการให้ประวัติแชท LINE OA อยู่ถาวรข้ามการ Deploy 100% ต้องผูกฐานข้อมูล **PostgreSQL ภายนอก (เช่น Render PostgreSQL / Supabase / Neon)** ผ่านตัวแปร `DATABASE_URL`

### ⚠️ 3.4 การเชื่อมต่อ Token ของอีก 3 แบรนด์ในระบบ (`มิสเตอร์บุก`, `PADA AI`, `AIFY`) และ Instagram DM
